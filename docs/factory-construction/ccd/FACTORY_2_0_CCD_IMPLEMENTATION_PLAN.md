Factory 2.0 already has a Complete Continuity Dossier that mixes permanent operating law, ephemeral technical snapshot, and Integration/CB inventory. - **does not** draft the CCD body;

After this Plan is audited and documentarily committed, CCD body drafting requires a **separate Mandate**.

## 8. Estrategia de construcción

### 8.1 Method

1. **Extract, do not invent** — permanent rules from Continuity Class 1 / §§1, 20–21, 27–29, 34 and Discovery Adiciones 1–7.  
2. **Pointer, do not duplicate** — Blueprint, Master Plan, Auditoría Maestra, Status.  
3. **Partition** — permanent law → CCD; ephemeral state → State Continuity Record.  
4. **Reconcile observations in CCD prose** per clauses below — without editing Discovery.  
5. **Draft under Mandate only** after this Plan is audited and documentarily committed.  
6. **Publish CCD** only under Adición 1 session-close discipline (commit + authorized push + HEAD verify + clean tree).

### 8.2 OBS resolutions (binding planning clauses)

#### OBS-CCD-DISCOVERY-01 — Git / push reconciliation

**CCD MUST state:**

1. GitHub is the **sole shared official development reference** (Adición 1).  
2. **No** two official development lines; **no** partial syncs.  
3. Session **officially closed** only when Adición 1 checklist is complete, including **authorized** push + verified published HEAD + clean tree.  
4. Continuity §28 “no push without express order” remains: push for session close is **not** a standing right; it is **required for official close** **when** Director/protocol **authorizes remote close** of that block/session.  
5. Until authorized push/close completes, session remains **not officially closed**; **no** independent new block may start.  
6. CCD **never** grants generic push/merge/deploy authority by mere existence.  
7. Ahead/behind counts in prose are **non-authoritative**; always re-verify Git READ_ONLY.

#### OBS-CCD-DISCOVERY-02 — Continuity ↔ CCD succession

**CCD MUST state (authority map):**

| Category | Official authority |
|----------|-------------------|
| Domain architecture (motors, FFO, catalogs) | Auditoría Maestra / FFO corpus |
| Construction sequence CB-00…CB-19 | Blueprint |
| Integration roadmap / P-INT catalog / phases | Integration Master Plan |
| What a block delivered | Status / Closeout of that block |
| Executable technical state | Code + validators at verified Git commit |
| Authorization / Mandates / parking / stop / ops direction | Explicit Director decisions + issued Mandates |
| **Continuity operating law (permanent)** | **CCD** (once approved) |
| **Reconciled operational state** (ACTIVE IMPLEMENTATION, NEXT BLOCK, matrices, tip SHAs as snapshot) | **State Continuity Record** (successor role of current Continuity dossier) |
| Shared official line of development | GitHub published HEAD of the official branch |

**Succession instrument (CCD-B12):** after CCD approval, the existing Continuity dossier **MUST**:

- cite CCD as sole continuity-law authority;  
- stop competing as second protocol constitution;  
- retain or evolve as **State Continuity Record** only;  
- be updated by a **separate documentary Mandate** (not silently inside CCD draft Mandate unless Director explicitly combines scopes).

Until that succession commit is published, dual-consolidation risk remains operationally open; CCD draft MUST already contain the map above so Adición 6 is satisfied in the CCD text itself.

#### OBS-CCD-DISCOVERY-03 — Classification purpose vs Factory frontier

**CCD MUST state:**

- Permanent purpose includes improving quality of Deal / Premium / Diamond classification **as a system objective**.  
- Factory **does not alone** assign commercial classification / `access_tier` (Continuity §22).  
- Decision Engine / Product / Marketplace remain sovereign downstream (Master Plan).  
- Factory contributes intelligence, evidence, legitimacy, and handoff quality toward that objective.

#### OBS-CCD-DISCOVERY-04 — Voids (Team Protocol / FSR / MCD file)

**CCD MUST:**

- consolidate Carlos↔Manolo protocol from Continuity §§27–29 / §34 + Adición 1;  
- **not** invent `FACTORY_TEAM_PROTOCOL_MVP`;  
- define **relation** to FSR when present; not invent full FSR series;  
- refer domain constitution as **Auditoría Maestra / FFO corpus**, not a nonexistent single `MCD` file unless Director later names one.

#### OBS-CCD-DISCOVERY-05 — Domains / programs without invented architecture

**CCD MUST:**

- declare evolution organized by **domains** and **programs** as **documentary governance**;  
- require every program to cite **existing** official blocks (Master Plan / Continuity / Status);  
- prohibit programs that create new CB construction or reopen closed construction;  
- affirm indicative lists ≠ authorization (Continuity §30);  
- **MUST NOT** rewrite Master Plan Fases/P-INT;  
- **MUST NOT** freeze inside CCD a closed engineering inventory that invents components.

**Plan stance on closed program catalog:**  
Out of scope for inventing new programs. Optional **non-constitutional annex** listing Master Plan phase residuals as *organizational labels* may be added later only by Director Class 1. Default CCD chapter 11 = **rules only**.

#### OBS-CCD-DISCOVERY-06 — Dual anchoring / single interpretation

If any evolution annex or State Record references a block:

- **one** official interpretation per block (Status/Closeout prevails for delivery; Master Plan for catalog intent; CCD for continuity law);  
- no parallel official readings.
