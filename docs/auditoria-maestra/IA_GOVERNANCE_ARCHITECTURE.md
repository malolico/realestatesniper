# I. Definición constitucional de la IA en Factory

## I.1 ¿Qué es la IA dentro de Factory?

La **Inteligencia Artificial en Factory** es el conjunto de **capacidades asistivas computacionales** gobernadas que:

| Propiedad | Definición |
|-----------|------------|
| **Naturaleza** | Herramienta subordinada — no actor soberano |
| **Invocación** | Solo por Motor, Loop o Enjambre catalogado — nunca autónoma |
| **Alcance** | Funciones declaradas en catálogo futuro AIA — no misión abierta |
| **Salida** | Sugerencias, borradores, scores auxiliares, logs — **nunca** actos factory |
| **Epistemología** | Inferencia siempre E1/E2 hasta corroboración motor |
| **Trazabilidad** | Reasoning log funcional obligatorio |
| **Neutralidad** | Independiente de proveedor o arquitectura modelo |

La IA Factory **no es** una entidad con voluntad, presupuesto propio ni autoridad constitucional.

## I.2 ¿Cuál es su misión?

> **Amplificar la eficacia de Motores, Loops y Enjambres en la producción y perfeccionamiento de conocimiento calibrado — sin alterar la cadena soberana de evidencia, sin decidir y sin sustituir actores constitucionales.**

La misión incluye:

- Asistir normalización, enriquecimiento y detección de patrones bajo supervisión motor
- Asistir evaluación de beneficio marginal y priorización en Loops
- Asistir coordinación documental y síntesis de estado en Enjambres
- Cuantificar y declarar incertidumbre de inferencias
- Producir explicaciones funcionales auditables
- **Nunca** elevar confianza C ni evidencia E sin acto motor verificador

## I.5 ¿Cómo coopera con los Motores?

| Relación | Regla |
|----------|-------|
| **Invocación** | Motor declara funciones AIA autorizadas en ficha futura |
| **Dirección** | Motor **solicita** asistencia — IA **responde** |
| **Validación** | Salida IA es **input candidato** — Motor produce knowledge delta |
| **E/C** | Motor asigna E y C final — IA sugiere como máximo E1/E2 |
| **Prohibición** | IA no sustituye ejecución motor ni misión MMA |
| **Evidencia** | Toda salida IA genera evidence ref auxiliar en MOT-EVD-01 |

## I.6 ¿Cómo coopera con los Loops?

| Relación | Regla |
|----------|-------|
| **Invocación** | Loop puede invocar FUN-RNK, FUN-GAP, FUN-UNC para evaluar Δ |
| **Decisión** | Loop **decide** re-ejecución — IA solo informa |
| **Presupuesto** | IA no consume presupuesto epistémico — cuenta como C_assist |
| **Prohibición** | IA no activa Loop; no declara agotamiento |
| **Auditoría** | Sugerencias IA en loop_ledger como advisory |

## I.7 ¿Cómo coopera con los Enjambres?

| Relación | Regla |
|----------|-------|
| **Invocación** | Enjambre puede invocar FUN-CRD, FUN-EXP, FUN-UNC en misión |
| **Coordinación** | IA **no orquesta** — Enjambre orquesta; IA documenta estado |
| **Consenso** | IA puede sugerir CS auxiliar — Enjambre calcula CS oficial |
| **Prohibición** | IA no constituye Enjambre; no envía SWA-OUT |
| **MSA-15** | IA asiste — no sustituye |

## I.8 ¿Cómo interactúa con las Evidencias?

| Relación | Regla |
|----------|-------|
| **Registro** | Toda invocación IA → evidence aux ref tipo `AIA-assist` |
| **E máximo** | E1 inferencia; E2 hypothesis — salvo corroboración motor |
| **Conflicto** | IA señala — MOT-EVD-02 decide |
| **Suficiencia** | IA no declara sufficiency |
| **Lineage** | model_id + prompt_hash + input_refs en ledger |

## I.9 ¿Cómo debe gestionar incertidumbre?

| Regla | Enunciado |
|-------|-----------|
| **UNC-01** | Toda salida IA incluye **uncertainty_aux** score 0–1 |
| **UNC-02** | uncertainty_aux **no sustituye** US Enjambre ni C motor |
| **UNC-03** | uncertainty_aux > 0.6 → etiqueta `low_confidence` Obl. |
| **UNC-04** | Calibración periódica vs outcomes motor |
| **UNC-05** | Abstención Obl. si uncertainty_aux > umbral patrón |

## I.10 ¿Cómo debe declarar inferencias?

| Regla | Enunciado |
|-------|-----------|
| **INF-01** | Toda inferencia etiqueta `inference_type`: deductive / inductive / analogical |
| **INF-02** | E asignado por motor post-validación — IA propone E1 máximo |
| **INF-03** | Campo `inference_basis` lista inputs referenciados |
| **INF-04** | Inferencia silenciosa = violación LS-11 |
| **INF-05** | Inferencia en bloque C1 Obl. **prohibida** sin VER motor |

## I.11 ¿Cómo distinguir hechos de hipótesis?

| Tipo | Criterio | E máximo IA | C máximo IA |
|------|----------|-------------|-------------|
| **Hecho verificado** | Corroborado fuente DSO + motor | — (motor asigna) | — |
| **Hecho inferido** | Cadena lógica desde E3/E4 | E1 propuesto | C4–C5 propuesto |
| **Hipótesis** | Escenario no verificado | E2 propuesto | C4–C5 propuesto |
| **Especulación** | Sin base DDI | **Prohibido** | — |

**Regla:** IA **solo propone** filas inferido/hipótesis — Motor **clasifica** definitivo.

## I.12 ¿Cómo justificar conclusiones?

**Marco JST (Justificación):**

| Campo | Obligatorio | Descripción |
|-------|-------------|-------------|
| **conclusion** | Sí | Enunciado conclusión asistiva |
| **premises** | Sí | Premisas con refs DDI/fuente |
| **reasoning_chain** | Sí | Pasos funcionales numerados |
| **counterarguments** | Recomendado | Alternativas consideradas |
| **confidence_aux** | Sí | Score 0–1 |
| **limitations** | Sí | Límites conocidos |

**Regla JST-01:** Conclusión sin reasoning_chain = salida inválida — descarte.

## I.13 ¿Cómo documentar razonamiento funcional?

**Reasoning Log (RLG) — estructura conceptual:**

```text
RLG-{invocation_id}
├── invoker_type        : MOT | LOOP | SWM
├── invoker_id          : MOT-XX-NN | LOOP-XX | swarm_id
├── aia_function        : FUN-XX
├── model_slot          : SLOT-XX (neutral — no vendor)
├── input_fingerprint   : hash inputs
├── output_fingerprint  : hash output
├── reasoning_chain     : JST premises → conclusion
├── uncertainty_aux     : 0–1
├── inference_tags      : [E1|E2, inference_type]
├── timestamp           : ISO
└── retention           : vida activo + 7 años
```

**Regla RLG-01:** Sin RLG no hay salida IA válida para consumo motor.

## I.14 ¿Cómo se audita?

| Tipo | Frecuencia | Objeto |
|------|------------|--------|
| **Por invocación** | Continua | RLG completo |
| **Por función AIA** | Mensual | Calibration uncertainty_aux |
| **Por motor** | Trimestral | % salidas IA aceptadas vs rechazadas |
| **Constitucional** | Anual | IGA compliance |
| **Forense** | Ad hoc | PRH violation |

**Hallazgos críticos:** PRH-EC, PRH-EVD, PRH-DEC → suspensión función AIA + revisión Board.

## I.15 ¿Cómo se sustituye un modelo?

| Fase | Acción |
|------|--------|
| **Declaración** | Nuevo model_slot registrado — vendor-neutral |
| **Equivalencia** | Matriz funcional FUN-XX — no benchmark opaco |
| **Dual-run** | Período paralelo obligatorio clase C |
| **Cutover** | Motor/Loop declara versión activa |
| **Retiro** | Histórico RLG preservado |
| **Rollback** | Slot anterior reactivable ≤24h conceptual |

**Regla SUB-01:** Sustitución **no altera** misión motor ni umbral E/C — solo medio computacional.

## I.16 ¿Cómo conviven múltiples modelos?

| Patrón | Código | Uso |
|--------|--------|-----|
| **Primary + Challenger** | MLT-PC | Challenger señala divergencia — motor decide |
| **Ensemble advisory** | MLT-ENS | ≥2 slots — disagreement log Obl. |
| **Specialist routing** | MLT-SPC | FUN distinto → slot distinto |
| **Fallback** | MLT-FBK | Slot primario fail → secundario — degradación declarada |

**Reglas multi-modelo:**

| Regla | Enunciado |
|-------|-----------|
| **MLT-01** | Promedio de outputs IA **prohibido** para E/C |
| **MLT-02** | Disagreement > umbral → escala motor VER |

| **MLT-04** | Ensemble no sustituye MOT-EVD-02 |

| Principio | Enunciado |
|-----------|-----------|
| **A-01 — Subordinación** | IA sirve a la arquitectura — no la gobierna |
| **A-02 — Asistencia no sustitución** | Motor produce; IA amplifica |
| **A-03 — Epistemología honesta** | Inferencia etiquetada — nunca silenciosa |
| **A-04 — Evidencia soberana** | MOT-EVD prevalece — IA no arbitra |
| **A-05 — Neutralidad tecnológica** | Arquitectura válida con cualquier modelo futuro |
| **A-06 — Trazabilidad total** | RLG obligatorio |
| **A-07 — Abstención virtuosa** | No responder > alucinar |
| **A-08 — Sustituibilidad** | Ningún modelo es eterno |
| **A-09 — Transparencia funcional** | Explicar en términos DDI — no caja negra opaca |
| **A-10 — No expansión** | IA no crea conocimiento fuera DDI |

## II.2 Cadena de autoridad

```text
CONSTITUCIÓN (MPI, DKN, DDI, DSO, FCC, MMA, MLA, MSA, IGA)
        ↓
SOURCES → CAPABILITIES → MOTORS → EVIDENCE
        ↓                    ↓
      LOOPS ──────────→ ENJAMBRES
        ↓                    ↓
              IA (asistiva — subordinada a invocador)
        ↓
CONOCIMIENTO → DECISION → PROJECTION → PRODUCTO
```

**Ley:** La IA **no aparece** en la cadena soberana — solo en rama asistiva punteada.

## II.3 IA × Enjambre × Motor (clarificación)

| Motor | Sí — invoca FUN | No |
| Loop | Sí — invoca FUN | No |

| MOT-EVD | No — registro only | No |
