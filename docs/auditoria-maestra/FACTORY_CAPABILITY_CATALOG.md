# FACTORY CAPABILITY CATALOG

**Catálogo Oficial de Capacidades Permanentes — Auditoría Maestra RealEstateSniper Factory 2.0**

**Autoridad:** Undécimo documento oficial de la Auditoría Maestra. Tercer documento de la **Fase II — Producción del Conocimiento**. Deriva obligatoriamente del **MASTER PROPERTY INTELLIGENCE INDEX**, de la **DIAMOND KNOWLEDGE CONSTITUTION**, del **Diamond Data Inventory** (2.265 elementos, 44 dominios MPI), de la **DIAMOND SOURCES & ORGANISMS ARCHITECTURE** y del **MASTER MOTORS ARCHITECTURE**.  
**Alcance:** Definir las **capacidades permanentes** de Factory 2.0 — misiones estables de producción de conocimiento que agrupan futuros motores, loops, enjambres y funciones asistivas sin definirlos aún.  
**Exclusión expresa:** Motores concretos, loops, enjambres, IA, implementación, programación, APIs, tecnología y orquestación técnica.

**Pregunta rectora de este documento:**

> *¿Qué capacidades permanentes debe poseer Factory para dominar los 44 dominios MPI y producir los 2.265 elementos del inventario Diamond — con estabilidad constitucional aunque los motores cambien?*

---

## Posición en la arquitectura Factory

```text
MPI + DKN + DDI          → QUÉ conocimiento (cerrado)
Sources Architecture     → DE DÓNDE (procedencia)
FACTORY CAPABILITY CATALOG → QUÉ CAPACIDADES permanentes (este documento)
Master Motors Architecture → CÓMO se organiza un motor
Official Motor Catalog   → QUIÉN produce (instancias) — pendiente
Loops / Swarms / IA      → CUÁNDO y CÓMO coordinan — pendiente
Decision → Projection → Product
```

| Capa | Estabilidad | Naturaleza |
|------|-------------|------------|
| **DDI** | Alta — enmienda constitucional | Inventario |
| **Capacidades** | **Muy alta — este catálogo** | Misión permanente |
| **Motores** | Media — versionados y sustituibles | Instancia productora |
| **Loops/Enjambres** | Media-baja | Orquestación |

**Ley de estabilidad:** Las capacidades **perduran** cuando los motores se sustituyen. Un motor sin capacidad padre **no es legítimo**.

# I. Definición constitucional de Capacidad

## I.1 ¿Qué es una Capacidad?

Una **Capacidad Factory** es una **misión permanente y soberana** de producción de conocimiento con:

| Atributo | Definición |
|----------|------------|
| **Identidad canónica** | Código CAP-XX y nombre institucional inmutable en esencia |
| **Misión** | Propósito epistémico durable — no implementación |
| **Ámbito MPI** | Dominios del índice maestro que cubre |
| **Ámbito DDI** | Partes y elementos del inventario que alimenta |
| **Producción autorizada** | Tipos de conocimiento que puede emitir |
| **Prohibiciones** | Límites constitucionales de la capacidad |
| **Cooperación** | Relaciones con otras capacidades |
| **Gobernanza** | Métricas, evolución y auditoría |

## I.2 Capacidad vs Motor vs Loop vs Enjambre

| Entidad | Metáfora | Pregunta que responde |
|---------|----------|----------------------|
| **Capacidad** | Ministerio | *¿Qué misión permanente existe?* |
| **Motor** | Oficina operativa | *¿Quién ejecuta la producción?* |
| **Loop** | Calendario / ciclo | *¿Cuándo se re-ejecuta?* |
| **Enjambre** | Coordinación multi-motor | *¿Cómo convergen varios motores?* |
| **IA (futuro)** | Asistente | *¿Qué asiste sin decidir?* |

**Regla:** Una capacidad puede contener **0..N motores** a lo largo del tiempo. Nunca al revés.

## I.3 Lo que una Capacidad NUNCA hace

| Prohibición | Razón |
|-------------|-------|
| Asignar `access_tier` o precio | Producto |
| Emitir Decision-Diamond o Projection-Diamond | Actos soberanos separados |
| Publicar en Marketplace | Producto |
| Expandir el DDI | Ley de no expansión |
| Sustituir evidencia soberana (CAP-20) | Jerarquía probatoria |
| Operar sin fuentes catalogadas | DSO |
| Mezclar misión con otra capacidad sin cooperación declarada | Anti-duplicidad |

# II. Filosofía de capacidades

## II.1 Tesis rectora

> **Factory es un estado de capacidades permanentes, no un zoo de motores.**

Los motores nacen, versionan y mueren. Las capacidades **definen la forma del estado** que Factory debe ser capaz de mantener sobre cualquier activo Diamond.

## II.2 Principios

| # | Principio |
|---|-----------|
| **C1** | Una capacidad = una misión dominante clara |
| **C2** | Cobertura MPI completa — ningún dominio huérfano |
| **C3** | Estabilidad constitucional > optimización táctica |
| **C4** | Cooperación explícita entre capacidades |
| **C5** | CAP-20 (Evidencia) es árbitro transversal |
| **C6** | CAP-21 (Síntesis) no crea hechos — integra |
| **C7** | CAP-22 (Ejecutivo) no sustituye corpus |
| **C8** | Evolución de capacidad = enmienda FCC — no drift |
| **C9** | Métricas por capacidad — no solo por motor |
| **C10** | Capacidad sin cobertura medida es capacidad nominal |

# VI. Evolución de capacidades

| Tipo cambio | Proceso | Impacto motores |
|-------------|---------|-----------------|
| **Patch** | Clarificación misión sin cambio MPI | Motores sin cambio MAJOR |
| **Minor** | Nuevo sub-ámbito dentro mismo dominio MPI | Motores nuevos opcionales |
| **Major** | Nuevo dominio MPI (enmienda MPI+DDI) | Re-catalogación motores |
| **Split** | Dividir capacidad | Dual-run transición |
| **Merge** | Fusionar capacidades | Deprecación motores huérfanos |
| **Retire** | Retirar capacidad | Solo si MPI elimina dominio |

**Ley:** Capacidad **no desaparece** por obsolescencia tecnológica — solo por enmienda constitucional.
