# I. Definición constitucional del Enjambre

## I.1 ¿Qué es un Enjambre?

Un **Enjambre** (Swarm) es una **unidad temporal de coordinación y resolución** en Factory 2.0 con las siguientes propiedades:

| Propiedad | Definición |
|-----------|------------|
| **Identidad** | Código de patrón + instancia de misión + factory_key / cohort scope |
| **Temporalidad** | Nace con derivación; muere al finalizar, agotar o escalar |
| **Derivación** | **Obligatoria** desde un Loop catalogado OLC — nunca espontánea |
| **Coordinación** | Orquesta motores, loops, capacidades, evidencias y fuentes en paralelo o feedback cruzado |
| **Misión** | Resolver un problema epistémico complejo no resoluble secuencialmente |
| **Salida** | Informe de convergencia + estado epistémico actualizado + handoff al Loop origen |
| **Límites** | No produce producto; no decide comercialmente; no sustituye Decision |

Un Enjambre **no es** motor, loop, producto, tier, agente IA autónomo ni acto Decision.

## I.2 ¿Cuál es su misión?

> **Coordinar la convergencia simultánea o iterativa de múltiples actores factory para resolver un problema epistémico complejo — devolviendo resultado calibrado al Loop derivador sin crear conocimiento primario no trazable ni usurpar actos soberanos aguas abajo.**

La misión incluye:

- Recibir mandato formal del Loop derivador con objetivo, presupuesto y actores autorizados
- Orquestar ejecución coordinada de ≥3 motores y/o intervención de loops según patrón
- Gestionar feedback cruzado entre salidas — no promediar conflictos
- Medir consenso e incertidumbre residual del resultado
- Escalar conflictos probatorios a MOT-EVD-02 cuando corresponda
- Devolver handoff estructurado al Loop origen
- Disolverse al completar — no persistir como entidad permanente

## I.3 ¿Qué tipos de problemas justifican un Enjambre?

| Clase problema | Código | Criterio de justificación |
|----------------|--------|---------------------------|
| **Convergencia multi-señal** | PRB-CVG | ≥3 motores SIG/productores con feedback cruzado; autenticidad distress |
| **Conflicto multi-dominio** | PRB-EVD | ≥3 dominios MPI en conflicto; MOT-EVD-02 requiere coordinación previa |
| **Reconstrucción temporal** | PRB-CHR | Cronología requiere motores JUD+LFE+SIG+MOT simultáneos |
| **Integración económica** | PRB-ECO | FIN+MKT+HAZ interdependientes — inputs circulares |
| **Fan-in pre-síntesis** | PRB-SYN | Sufficiency multi-capa con divergencia persistente |
| **Legitimidad compuesta** | PRB-LEG | Title+lien+owner+documento — challenge pipeline paralelo |
| **Investigación paralela** | PRB-INV | ≥3 hipótesis distress con búsqueda simultánea |
| **Identidad compuesta** | PRB-IDN | Tri-fuente assessor+recorder+MLS irreconciliable secuencial |
| **Negociación multi-factor** | PRB-NEG | Leverage requiere SYN+FIN+MOT+DCN inputs cruzados |

**Regla PRB-00:** Si un problema se resuelve con **un motor** o **un loop secuencial** (STR-1..STR-7) — **no** justifica Enjambre.

## I.4 ¿Cuándo nace un Enjambre?

| Condición | Descripción |
|-----------|-------------|
| **Derivación Loop** | Loop catalogado declara STR-6 o ESC-S según MLA/OLC |
| **Mandato formal** | Handoff FIN-H con factory_key, objetivo, actores, presupuesto |
| **Elegibilidad** | P0–Pn satisfechas; compliance clear; identidad mínima resuelta |
| **Aceptación** | Swarm Registry Authority acepta patrón + instancia (conceptual) |
| **Registro** | swarm_id único + loop_parent + pattern_code |

**Nacimiento prohibido:** Spontáneo; sin Loop padre; motor invoca Enjambre; producto solicita Enjambre.

## I.5 ¿Cuándo desaparece un Enjambre?

| Condición | Código | Efecto |
|-----------|--------|--------|
| **Misión cumplida** | DIE-S | Handoff resultado → Loop origen → disolución |
| **Agotamiento** | DIE-X | Sin convergencia posible → informe agotamiento → disolución |
| **Presupuesto** | DIE-B | Presupuesto swarm consumido → handoff parcial |
| **Escalado** | DIE-E | Evidence Council / Architecture Board asume |
| **Compliance veto** | DIE-C | MOT-CMP-01 revoca — disolución inmediata |
| **Timeout misión** | DIE-T | SLA swarm excedido — handoff con estado parcial |

**Regla:** Enjambre **nunca** persiste tras DIE-* — solo su informe y ledger histórico.

## I.6 Lo que un Enjambre NUNCA es

| Anti-patrón | Por qué es ilegítimo |
|-------------|----------------------|
| **Grupo de IA** | IA asiste — no constituye Enjambre |
| **Loop permanente** | Loop es entidad permanente de calidad |
| **Motor macro** | Motor tiene misión única DDI — Enjambre coordina varios |
| **Decisor** | Decision-Diamond es acto soberano separado |
| **Productor de producto** | Projection y Producto aguas abajo |
| **Pool de reintentos** | Reintento es técnico — fuera de MSA |
| **Promediador de evidencia** | LS-09 — MOT-EVD-02 arbitra mérito |

## I.7 Lo que un Enjambre NUNCA debe hacer

| Prohibición | Razón constitucional |
|-------------|----------------------|
| **Asignar `access_tier` o precio** | Producto |
| **Emitir Decision-Diamond** | Acto soberano |
| **Publicar Marketplace** | Producto |
| **Inventar hechos** | MMA-02 / LS-11 |
| **Promediar conflictos E** | LS-09 / MOT-EVD-02 |
| **Existir sin Loop derivador** | LLC-15 / LLK-14 |
| **Invocar motor no OMC** | OMC-01 |
| **Redefinir misión motor o CAP** | LM-17 / LC-19 |
| **Fusionar capacidades** | FCC — Enjambre coordina, no fusiona |
| **Persistir post-misión** | Temporalidad constitucional |
| **Bypass MOT-CMP-01** | P0 inviolable |
| **Sustituir MOT-SYN / MOT-EXE** | CAP-21 / CAP-24 soberanos |

# II. Filosofía de los Enjambres

## II.1 Principios fundacionales

| Principio | Enunciado |
|-----------|-----------|
| **S-01 — Temporalidad sobre permanencia** | Enjambre existe solo mientras el problema lo exige |
| **S-02 — Complejidad justificada** | Sin PRB-00 superado — no nace Enjambre |
| **S-03 — Derivación soberana** | Solo Loop catalogado puede crear Enjambre |
| **S-04 — Coordinación sobre producción** | Enjambre orquesta — motores producen |
| **S-05 — Consenso calibrado** | Convergencia medida — no votación ni promedio |
| **S-06 — Incertidumbre declarada** | Residual siempre explícito en handoff |
| **S-07 — Evidencia prevalece** | MOT-EVD-01/02 arbitran — Enjambre facilita |
| **S-08 — Handoff obligatorio** | Resultado siempre vuelve al Loop padre |
| **S-09 — Disolución limpia** | Morir bien es virtud constitucional |
| **S-10 — Factory soberano** | Enjambre sirve a Factory — no a Producto |

## II.2 Motor × Loop × Enjambre

```text
MOTOR     → Produce conocimiento (QUÉ)           — permanente
LOOP      → Perfecciona calidad (CUÁNDO/POR QUÉ)   — permanente
ENJAMBRE  → Coordina resolución compleja (CÓMO)     — TEMPORAL
IA        → Asiste actores (futuro)                 — subordinada
```

| Dimensión | Motor | Loop | Enjambre |
|-----------|-------|------|----------|
| **Duración** | Permanente | Permanente | Temporal |
| **Disparador** | Loop / evento | Activador epistémico | Derivación Loop STR-6/ESC-S |
| **Actores** | 1 misión | Motores supervisados | ≥3 motores/loops coordinados |
| **Salida** | Knowledge delta | Decisión re-ejecución | Informe convergencia |
| **Fin** | Manifest | Reposo / agotamiento | DIE-S / DIE-X / DIE-E |
| **Registro** | Motor run | Loop ledger | Swarm mission ledger |

## II.3 Enjambre vs IA (futuro)

| Dimensión | Enjambre | IA asistiva (futuro) |
|-----------|----------|----------------------|
| **Naturaleza** | Unidad coordinación factory | Herramienta subordinada |
| **Autoridad** | Derivada de Loop + MSA | Gobernanza IA — documento futuro |
| **Producción** | No produce hechos primarios | No produce hechos primarios |
| **Decisión** | No decide | No decide |
| **Relación** | Puede **usar** IA como actor asistivo | **Nunca** constituye Enjambre por sí sola |

# III. Relaciones constitucionales

## III.1 Cadena soberana con Enjambres

```text
FUENTES (DSO)
        ↓
MOTORES (52)  ←—— coordinados por ——→  ENJAMBRE (temporal)
        ↑                                      ↑
LOOPS (24)  ——— derivan —──────────────────┘
        ↓
CONOCIMIENTO → EVIDENCIAS (MOT-EVD) → SÍNTESIS → DECISION → PRODUCTO
                      ↑
              Enjambre facilita — no arbitra mérito
```

## III.2 ¿Cómo se relaciona con los Loops?

| Relación | Regla |
|----------|-------|
| **Padre** | Todo Enjambre tiene **exactamente un** Loop derivador catalogado |
| **Derivación** | Loop declara STR-6 o ESC-S; Enjambre **no** auto-nace |
| **Mandato** | Loop envía handoff: objetivo, actores, presupuesto, estrategias agotadas |
| **Supervisión** | Loop padre mantiene oversight — puede abortar con DIE-C |
| **Retorno** | Enjambre devuelve FIN-H a Loop padre — nunca a Producto |
| **Lock** | Durante misión swarm, Loop padre **retiene** lock motores coordinados (extiende LK-01) |

## III.3 ¿Cómo recibe trabajo?

**Protocolo de recepción SWA-IN:**

| Campo mandato | Obligatorio | Descripción |
|---------------|-------------|-------------|
| **swarm_pattern** | Sí | Código patrón MSA (§ IV) |
| **loop_parent** | Sí | LOOP-XX-YY-ZZ derivador |
| **factory_key** | Sí (AST) | Activo o cohort scope |
| **objective_epistemic** | Sí | Problema PRB-XX a resolver |
| **authorized_motors** | Sí | Lista cerrada OMC |
| **authorized_loops** | No | Loops auxiliares si aplica |
| **authorized_caps** | Sí | CAP-XX involucradas — referencia |
| **budget_swarm** | Sí | Presupuesto epistémico misión |
| **strategies_exhausted** | Sí | STR Loop previas agotadas |
| **deadline** | Recomendado | SLA misión |
| **evidence_state** | Sí | Snapshot MOT-EVD-01 |

**Regla SWA-IN-01:** Sin mandato completo — rechazo de nacimiento.

## III.4 ¿Cómo devuelve resultados?

**Protocolo de retorno SWA-OUT:**

| Campo handoff | Obligatorio | Descripción |
|---------------|-------------|-------------|
| **swarm_id** | Sí | Identidad misión |
| **outcome_code** | Sí | DIE-S / DIE-X / DIE-B / DIE-E |
| **consensus_score** | Sí | § XII |
| **uncertainty_score** | Sí | § XIII |
| **convergence_report** | Sí | Narrativa estructurada — no IC |
| **motor_deltas** | Sí | Referencias manifests re-ejecutados |
| **evidence_updates** | Sí | IDs MOT-EVD-01 afectados |
| **residual_gaps** | Sí | Known gaps post-misión |
| **conflicts_escalated** | Si aplica | A MOT-EVD-02 |
| **recommendation_loop** | Sí | STR sugerida para Loop padre |
| **budget_consumed** | Sí | % presupuesto |

**Regla SWA-OUT-01:** Loop padre **acepta o rechaza** handoff — rechazo reabre misión o escala.

## III.5 ¿Cómo coopera con Factory?

| Relación | Regla |
|----------|-------|
| **Factory** | Enjambre es **órgano temporal** de Factory — no de Producto |
| **Decision** | Enjambre **alimenta** conocimiento — no emite Decision |
| **Projection** | Projection consume post-Decision — Enjambre no alcanza |
| **Producto** | **Prohibido** invocar Enjambre directamente |
| **Auditoría** | Swarm mission ledger es activo factory auditable |

# VI. Ciclo de vida del Enjambre

```text
MANDATO (Loop) → NACIMIENTO → COORDINACIÓN → CONVERGENCIA/AGOTAMIENTO → HANDOFF → DISOLUCIÓN
                      ↑              ↓                    ↓
                 REGISTRO      OBSERVABILIDAD      LEDGER PERMANENTE
```

| Fase | Estado | Descripción |
|------|--------|-------------|
| **Mandato** | PENDING | Loop envía SWA-IN |
| **Nacimiento** | BORN | swarm_id asignado; actores locked |
| **Coordinación** | ACTIVE | MOD-P/I/X/C/F en ejecución |
| **Convergencia** | CONVERGING | Midiendo consenso/incertidumbre |
| **Handoff** | RETURNING | SWA-OUT al Loop padre |
| **Disolución** | DEAD | DIE-* — entidad destruida |
| **Archivo** | ARCHIVED | Ledger preservado |

## VI.1 Estados operativos

| Estado | Significado |
|--------|-------------|
| **PENDING** | Esperando aceptación mandato |
| **BORN** | Registrado — pre-coordinación |
| **ACTIVE** | Coordinando motores |
| **CONVERGING** | Evaluando consenso |
| **STALLED** | Sin progreso Δ — riesgo DIE-X |
| **ESCALATING** | Derivando a Council |
| **RETURNING** | Handoff en curso |
| **DEAD** | Disuelto |
| **ABORTED** | DIE-C compliance |

# X. ¿Cómo gestiona conflictos?

## X.1 Jerarquía de conflicto

```text
1. Conflicto intra-motor     → MOT-VER del dominio
2. Conflicto inter-motor     → Enjambre facilita challenge MOD-C
3. Conflicto probatorio E    → MOT-EVD-02 (árbitro mérito)
4. Conflicto irresoluble     → Evidence Council (DIE-E)
```

## X.2 Reglas de conflicto

| Regla | Enunciado |

# XI. ¿Cómo mide el consenso?

## XI.1 Definición

**Consenso** es el grado de **alineación epistémica medible** entre salidas de actores coordinados sobre el objetivo de misión — no votación ni mayoría.

## XI.2 Dimensiones de consenso

| Dimensión | Peso | Medición conceptual |
|-----------|------|---------------------|
| **Alineación C** | 30% | % actores con C dentro de 1 nivel |
| **Alineación E** | 30% | % actores sin conflicto E activo |
| **Cobertura objetivo** | 25% | % elementos objetivo con valor no contradictorio |
| **Evidencia compartida** | 15% | % salidas con evidence ref común |

## XI.3 Escala consenso

| Score | Rango | Interpretación |
|-------|-------|----------------|
| **CS-5** | 0.90–1.00 | Convergencia fuerte — DIE-S candidato |
| **CS-4** | 0.75–0.89 | Convergencia aceptable |
| **CS-3** | 0.60–0.74 | Convergencia parcial — iterar |
| **CS-2** | 0.40–0.59 | Divergencia material — cambiar MOD |
| **CS-1** | <0.40 | Sin convergencia — DIE-X o DIE-E |

**Umbral DIE-S default:** consensus_score ≥ **0.75** salvo patrón declare otro.

---

# XII. ¿Cómo mide la incertidumbre?

## XII.1 Definición

**Incertidumbre** es el **residual epistémico** tras coordinación — lo que permanece desconocido, inferido o conflictivo.

## XII.2 Componentes incertidumbre

| Componente | Descripción |
|------------|-------------|
| **U_gap** | Densidad known gaps Obl. en objetivo |
| **U_inf** | Proporción E1/E2 inferido vs E3/E4 |
| **U_conf** | Conflictos abiertos / total elementos |
| **U_c** | Elementos con C4–C5 en objetivo |
| **U_src** | Dependencia fuente única en bloque crítico |

## XII.3 Escala incertidumbre

| Score | Rango | Interpretación |
|-------|-------|----------------|
| **US-1** | 0.00–0.20 | Baja — handoff limpio |
| **US-2** | 0.21–0.40 | Moderada — known unknowns Obl. |
| **US-3** | 0.41–0.60 | Alta — síntesis condicionada |
| **US-4** | 0.61–0.80 | Muy alta — readiness bloqueado |
| **US-5** | >0.80 | Crítica — DIE-X probable |

**Regla:** uncertainty_score **siempre** reportado en SWA-OUT — aunque DIE-S.

## XII.4 Consenso × Incertidumbre (matriz resultado)

| | US baja | US alta |
|---|---------|---------|
| **CS alta** | DIE-S — handoff óptimo | DIE-S condicionado — known unknowns |
| **CS baja** | DIE-X — datos contradictorios | DIE-E — escalar Council |
